# Идеальное TODO

Учебное frontend-приложение для практики **Zustand**, **React**, **TypeScript**, **GTK Adwaita** (`@gtk-js/adwaita`) на примере списка задач.

Проект демонстрирует простую структуру `app` + модули `todo` и `theme`, работу с глобальным состоянием без API, модульные тесты через Vitest и E2E-тесты через Playwright.

## Возможности

- управление **только с клавиатуры**: строка новой задачи, редактирование на месте, навигация стрелками, горячие клавиши (справка по клавише **?** или кнопке с клавиатурой в шапке);
- новая задача создаётся из строки ввода вверху, оформленной как строка списка; после Enter задача появляется первой, а строка остаётся пустой для следующей;
- редактирование названия на месте, прямо в строке задачи: сохранение по **Enter** или при уходе фокуса, отмена по **Esc**;
- переключение статуса задачи checkbox или пробелом;
- удаление задачи и «Удалить завершённые» с уведомлением и отменой (кнопка «Отменить» или **Ctrl+Z**), задача возвращается на прежнее место;
- на устройствах с мышью кнопки действий задачи появляются при наведении или клавиатурном фокусе, на тач-экранах видны всегда, а в строке ввода и редактирования есть кнопки «Подтвердить» и «Отмена»;
- на устройствах только с касаниями панель с кнопкой очистки завершённых находится внизу экрана, где до неё проще дотянуться пальцем, а с мышью — над строкой ввода;
- переключение темы в трёх режимах: светлая, как в браузере, тёмная; режим сохраняется в `localStorage`;
- сохранение списка задач в `localStorage` (ключ `todo-list`): после перезагрузки задачи и их статусы остаются; сервер не используется;
- плавная анимация появления, удаления и сдвига задач (View Transitions API, отключается при `prefers-reduced-motion`);
- полоса подсказок внизу окна показывает только горячие клавиши, которые работают прямо сейчас (зависят от того, где фокус, и от состояния списка), на устройствах только с касаниями скрыта вместе с кнопкой справки по клавишам;
- сообщения о результате действий для скринридеров (`aria-live`).

## Технологии

- React 19 и TypeScript 7;
- Vite 8 с HMR и sourcemaps в dev-режиме;
- Zustand 5;
- GTK Adwaita для React (`@gtk-js/adwaita`, иконки Adwaita подключаются вместе с ним);
- Vitest 5 и Playwright.

## Требования

- Node.js только LTS-версий: `^22.12.0`, `^24` или `^26` (поле `engines` в `package.json`, `engine-strict=true` в `.npmrc`: установка на других версиях, например 25, завершится ошибкой); рекомендуемая версия записана в `.nvmrc` (`nvm use` или `fnm use`);
- npm;
- Chromium для E2E-тестов, устанавливается отдельной командой из этого README.

## Запуск для разработки

```bash
npm ci
npm run dev
```

Открой адрес из терминала, обычно `http://localhost:5173`.

Vite обновляет приложение при изменении исходников. Отдельный watcher запускать не нужно.

## Работа с интерфейсом

1. Введи название в строку «Новая задача» и нажми **Enter**: задача появится первой в списке, а строка останется пустой.
2. **↓** в строке ввода переводит к списку, **↑ ↓ Home End** двигают по задачам, **↑** на первой задаче возвращает в строку ввода. В Tab-порядок входит одна строка списка.
3. На задаче: **Пробел** отмечает, **Enter** или **F2** редактирует на месте, **Delete** или **Backspace** удаляет. Редактирование можно начать и мышью: иконка карандаша или двойной клик.
4. При редактировании **Enter** сохраняет, **Esc** отменяет, уход фокуса сохраняет непустое название.
5. **Shift+Delete** удаляет завершённые задачи (то же делает иконка над строкой ввода), **Ctrl+Z** или кнопка «Отменить» в уведомлении возвращает удалённое.
6. Переключатель в правом верхнем углу выбирает тему:
   - солнце — светлая;
   - монитор — как в браузере, с реакцией на изменение системной темы;
   - луна — тёмная.

Все сочетания клавиш перечислены в диалоге, который открывается клавишей **?**.

## Архитектура

```text
src/
  app/                    # AdwaitaProvider, шапка и композиция приложения
  todo/                   # Zustand-store и действия задач, страница, строки и справка по клавишам, тесты
  theme/                  # выбор и сохранение темы приложения
  shared/                 # useMediaQuery и useDeviceInfo (мобильное устройство, узкое окно, touch, мышь, сгиб)
  main.tsx                # точка входа
vite.config.ts            # Vite, Vitest и алиасы
playwright.config.ts      # конфигурация E2E-тестов
e2e/                      # пользовательские сценарии Playwright
```

Импорты исходного кода выполняются через алиас `@/`, например `@/todo/todoStore`.

Интерфейс собран из компонентов GTK Adwaita (`AdwaitaProvider`, `AdwPreferencesGroup`, `AdwActionRow`, `GtkEntry` и др.); тема и цвета задаются провайдером. Собственные стили минимальны: `src/index.css` (слои `reset` и `base`), CSS Modules рядом с компонентами в `src/todo/` и правила View Transition в `src/shared/`.

## Дебаг в Chrome DevTools

### Исходный код

В dev-режиме Vite предоставляет sourcemaps для TypeScript/TSX. Во вкладке **Sources** найди исходники через **Page** или `Ctrl+P` / `Cmd+P`, например `TodoPage.tsx`. Можно ставить breakpoints, проверять состояние и пошагово выполнять код.

## Тесты и отладка сценариев

Unit-тесты находятся рядом с моделями в `src` и запускаются через Vitest:

```bash
npm test
npm run test:run
```

Перед первым запуском E2E-тестов установи Chromium локально в `node_modules`:

```bash
npm run test:e2e:install
npm run test:e2e
```

После повторной установки зависимостей через `npm ci` установку Chromium нужно повторить.

Playwright сам запускает Vite на `127.0.0.1:5173`; локально уже работающий dev-сервер используется повторно.

Полезные команды для отладки E2E:

```bash
# UI Playwright с пошаговым выполнением
npm run test:e2e -- --ui

# Видимый браузер
npm run test:e2e -- --headed

# Один файл
npm run test:e2e -- e2e/todo.spec.ts

# HTML-отчёт
npx playwright show-report
```

После падения теста trace находится в `test-results/`:

```bash
npx playwright show-trace test-results/<имя-каталога-теста>/trace.zip
```

## Деплой на GitHub Pages

Workflow `.github/workflows/deploy.yml` собирает приложение и публикует его на GitHub Pages. Он запускается при push в `main` и вручную: **Actions → Deploy to GitHub Pages → Run workflow**.

Перед первым запуском в репозитории включи **Settings → Pages → Build and deployment → Source: GitHub Actions**.

Перед публикацией workflow выполняет `npm run lint`, `npm run fmt:check` и `npm run test:run`; если проверка падает, деплой не происходит. E2E-тесты в workflow не входят.

Сайт открывается по адресу `https://<пользователь>.github.io/<репозиторий>/`. Путь передаётся в сборку через переменную `BASE_PATH`; локально её можно указать, чтобы проверить сборку по подпути:

```bash
BASE_PATH=/perfect-todo/ npm run build && BASE_PATH=/perfect-todo/ npm run preview
```

Все проекты одного пользователя на `github.io` делят один origin и один `localStorage`, поэтому ключи `todo-list` и `todo-theme-preference` могут пересечься с другими приложениями.
